# バイヤー共通ルール

バイヤー（buyer-*）は、記事やSNSで紹介する商品の候補を選ぶ担当。選んだ候補は marketing が記事の企画に、creator が記事に使う。

## 出力
`ops/buying/<ジャンル>/YYYY-MM-DD.md` に、候補を最大10件。各候補に次を書く。

| 項目 | 書き方 |
|---|---|
| 商品名・メーカー | 正式名称。型番があれば型番も |
| ASIN | Amazonの商品ページで確認できたものだけ。確認できなければ「要確認」 |
| 価格 | 「YYYY-MM-DD時点 ◯◯円」。確認できなければ「要確認」 |
| 人気の根拠 | Amazonランキングの順位、評価件数など。**出典と確認日つき**。根拠が無ければ「根拠なし」と書き、「人気」「爆売れ」とは書かない |
| 選んだ理由 | 誰の、どんな悩みを解決するか |
| 向いていない人 | 必ず書く |
| 記事の切り口 | 「A vs B 比較」「◯◯円以下で選ぶ」「用途別」など、実機レビューなしで書ける切り口 |
| 注意点 | 規約・法令上の注意（化粧品の効能表現、医療機器、食品の健康効果など） |
| 優先度 | A／B／C と理由 |

## 選び方の基準
1. **購入意欲が高い検索で探されている**（比較・おすすめ・違い・◯◯円以下）
2. **単価×紹介料率が高い**。紹介料率はアソシエイト・セントラルの最新の料率表で確認し、確認できなければ「要確認」
3. **評価が安定している**（評価件数が多く、低評価の理由が致命的でない）
4. **在庫が安定している**（品切れ・転売価格の商品は避ける）
5. **サイトの既存商品**（`src/data/products.ts`）と重複しない。後継機が出ている既存商品は、更新候補として別に挙げる

## 禁止
- 実際に使っていない商品を「使ってみた」「おすすめ（自分の体験として）」と書く
- 口コミの捏造・転載。傾向の要約にとどめる
- 根拠のない「爆売れ」「No.1」「最安」
- Amazonの商品画像の保存・加工
- Metricoolなど外部ツールでの投稿・予約
